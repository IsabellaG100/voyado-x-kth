Level 1

Manual Development

Traditional, fully manual software development with no AI involvement.

Core idea: everything is built directly by humans.
Level 2

AI as Reference & Suggestion

AI is used as an enhanced search engine, documentation assistant, or autocomplete tool.

Core idea: AI helps answer questions, not execute work.
Level 3

Snippet Generator

The developer asks AI to generate specific functions or snippets, then copy-pastes and integrates them into the codebase.

Core idea: AI produces code fragments; the human stitches them together.
★ Today's workshop
Level 4

Local AI Pair Programmer

AI is embedded in the IDE or CLI and can be instructed to make changes across files. It executes short, scoped tasks autonomously (~10 min) before returning control.

Core idea: AI actively modifies the codebase under direct human guidance.
Level 5

Task-Based Delegation

Humans assign complete tasks to AI instead of guiding step-by-step. The workflow becomes: specify task → assign → review. AI runs independently for longer intervals (~30 min).

Core idea: humans manage tasks, not individual coding steps.
Level 6

Initiative-Level Execution

Humans define larger initiatives. AI breaks them down into epics and tasks, executes them, and iterates independently. Systems can run for extended periods (days) without a human in the loop.

Core idea: humans define initiatives, AI plans and executes.
Level 7

Dark Factory

Humans provide vision, values, and strategic goals. AI determines what to build, defines initiatives, and fully implements them end-to-end.

Core idea: software development operates as an autonomous system.

Part 2 — Branching Strategy

Work in Parallel, Merge to Main

The code lives on GitHub with a default branch called main. In a real team, pushing directly to main causes conflicts. A branching strategy is an agreement on how to work in parallel.

main —————————————————————————— (always deployable)
  |
  └— feature/team-1 → commits → Push → PR → Review → Merge → Deploy

Create your branch immediately after cloning:

git checkout -b feature/team-[team-id]

Example: feature/team-1, feature/team-3, feature/team-5

This naming format is important — follow it exactly: feature/team-[team-id]

Part 2 — Step-by-Step Flow

Follow the Sequence

The AI guides you. Commit & push after every step — the next skill requires the previous artifacts.

#StepWhat happens
1Create branchgit checkout -b feature/team-[team-id]
2OnboardRun any command (e.g. /voyado-help) — it walks you through onboarding. Provide names & emails.
3Commit & pushCommit onboarding artifacts. Every skill needs the previous step committed.
4BrainstormTeam reads the mission & requirements together. AI skills guide the discussion.
5Create PRD/voyado-prd — answer questions, get a full PRD
6Plan Sprint/voyado-plan — break PRD into epics & stories
7Implement/voyado-impl — pick up stories one at a time, write the code
8Review/voyado-review — check code quality, fix issues
9ShipPush your code, create a Pull Request on GitHub, ask for a code review
10MergeWhen PR is approved, merge to main — CI/CD deploys automatically
11Demo!Each team presents their module to everyone

Check progress anytime: /voyado-help or /voyado-status
